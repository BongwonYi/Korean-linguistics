형태소 분석기에 문장을 넣으면 몇 초 만에 형태소가 나뉘고 품사 태그가 붙어 나온다. 손으로 하면 한 문장에 몇 분씩 걸리는 일이다. 발화 자료를 분석하거나 문법 현상을 확인할 때 분석기를 쓰면 시간을 크게 줄일 수 있다.

그렇다고 분석기가 내놓은 결과를 그대로 믿으면 안 된다. 이 문서에 실린 예는 모두 2026년 10월에 바른과 Kiwi에 직접 넣어 얻은 것인데, 두 분석기 모두 틀린 곳이 있었고 틀린 곳도 서로 달랐다. 분석기로 초안을 빠르게 만들고, 미심쩍은 곳만 골라 사람이 확인하는 방식이 가장 효율적이다.

아래에서는 이 과정을 다섯 단계로 나누어 설명하고, 분석기가 자주 틀리는 곳을 실제 결과와 함께 정리했다. 끝으로 발화 자료에서 형태소 수를 세는 방법을 덧붙였다.

이 문서에서 다루는 것

  1. 바른 형태소 분석기의 설정을 목적에 맞게 바꾸는 법
  2. 세종 품사 태그를 읽는 법
  3. 분석 결과에서 다시 확인해야 할 곳을 찾는 법
  4. 다른 분석기와 사전으로 결과를 검증하는 법
  5. 발화 자료의 형태소 수를 일관되게 세는 법
§ Ⅰ

쓰는 도구 Tools

분석기 두 개와 사전 두 개면 충분하다. 도구를 여러 개 갖추기보다 이 네 가지에 익숙해지는 편이 낫다.

주 도구

바른 형태소 분석기

bareun.ai/analyze

웹에서 로그인 없이 쓸 수 있고 한 번에 2,000자까지 넣을 수 있다. 형태소마다 확률과 출처가 함께 나오기 때문에 어디를 다시 봐야 하는지 알기 쉽다. 결과는 표, JSON, 그림(SVG/PNG)으로 볼 수 있다.

비교용

Kiwi(키위)

kiwi.bab2min.pe.kr

누구나 쓸 수 있는 공개 분석기다. 웹 데모가 있고, 파이썬(kiwipiepy)으로 자기 컴퓨터에서 많은 자료를 한꺼번에 처리할 수도 있다. 바른과 틀리는 곳이 달라서 결과를 견주어 보기에 좋다.

규범 확인

표준국어대사전

stdict.korean.go.kr

표제어로 실려 있는지, 품사가 무엇인지, 어떻게 활용하는지, 동형어 번호가 몇 번인지를 확인한다. 한 단어인지 두 단어인지, 어느 품사인지를 가릴 때 근거가 된다.

기본 사전

고려대 한국어대사전

네이버 국어사전에서 조회

말뭉치 용례를 바탕으로 만든 사전이어서 실제로 어떤 뜻과 용법으로 쓰이는지 보기에 좋다. 표준국어대사전과 판단이 다르면 두 가지를 모두 적고 근거를 밝힌다.

우리말샘

신어, 구어, 방언처럼 두 사전에 없는 말은 국립국어원 우리말샘(opendict.korean.go.kr)에서 찾아본다. 다만 누구나 참여해 만드는 사전이므로 규범을 따지는 근거로 삼기에는 약하다.

§ Ⅱ

바른 분석기 쓰는 법 Using Bareun

다섯 가지 설정

입력 칸 위에 스위치가 다섯 개 있다. 처음 열었을 때의 설정은 띄어쓰기를 바로잡아 주는 쪽에 맞춰져 있다. 언어 자료를 분석할 때는 원문을 그대로 두어야 하므로 설정을 바꾸어 쓰는 것이 좋다.

스위치기본권장이유 (실제 결과)
자동 붙여쓰기켜짐끔원문의 어절 경계가 바뀐다. 어절 수를 세거나 띄어쓰기 오류를 살펴보려면 원문이 그대로 남아 있어야 한다.
자동 띄어쓰기켜짐끔켜 두었더니 「봐봐」가 「봐」와 「봐」 두 어절로 나뉘었다. 아동 발화나 노래 가사처럼 띄어쓰기 자체가 분석 대상인 자료에서는 반드시 끈다.
자동 문장분리켜짐켬문장마다 번호를 매겨 준다. 문장 끝에 마침표나 물음표가 없으면 다음 문장과 붙여서 분석하므로 부호를 꼭 넣는다.
의미 구분 BETA꺼짐필요할 때켜면 형태 옆에 동형어 번호가 붙는다(눈001, 새006, 부시002). 어휘 의미를 다룰 때 쓸 만하지만, 번호는 사전에서 다시 확인해야 한다.
원형 분석(Raw)꺼짐켬끈 상태에서는 「공부하는」이 공부하/VV 한 덩어리로 나왔고, 켜니 공부/NNG + 하/XSV로 나뉘었다. 「시작했다」도 마찬가지였다. 형태소 단위로 분석하려면 켜 두어야 한다.
설정 확인

「새 분석」을 누르면 바로 전의 설정이 유지되지만, 페이지를 새로 열면 처음 설정으로 돌아간다. 분석 버튼을 누르기 전에 스위치 다섯 개를 한 번 확인하는 습관을 들이자.

결과 화면 읽기

결과는 세 가지 방식으로 볼 수 있다. ‘형태소 태깅’은 어절 아래에 형태소와 태그를 색깔별로 묶어 보여 주고, ‘형태소 테이블’은 같은 내용을 표로 정리해 준다. ‘JSON’은 프로그램에서 쓰는 원자료다. 결과를 옮겨 적을 때는 표가 가장 편하다. 표는 다음과 같이 생겼다.

번호어절형태태그품사확률(%)출처
4뭐지뭐NP대명사99.99학습 사전
이VCP긍정 지정사100학습 사전
지EC연결 어미56.74학습 사전
1시려워.시렵VA형용사99.70신조어

이 표에서 눈여겨볼 곳은 확률과 출처다.

확률은 분석기가 그 태그를 얼마나 확신하는지를 보여 준다. 대부분의 형태소가 99에서 100 사이로 나오기 때문에, 90 아래로 내려간 값이 있으면 바로 눈에 띈다. 위 표에서 「뭐지」의 「지」는 56.74였다. 말끝에서 스스로에게 묻는 표현이므로 연결어미가 아니라 종결어미(EF)로 보아야 한다. 확률이 낮다는 것은 분석기도 헷갈렸다는 뜻이다.

출처가 ‘학습 사전’이 아니면 한 번 더 살펴본다. ‘신조어’는 분석기가 모르는 말이어서 형태만 보고 짐작했다는 뜻이다. 「시려워」를 시렵/VA로 분석했지만 표준어는 「시리다」다. ‘내장 사전’은 사전에 통째로 실린 말을 한 덩어리로 처리했다는 뜻이므로, 원형 분석을 켜고 다시 분석해 본다.

「큰」을 크/VA + ᆫ/ETM으로 낸다. 어미 「-ㄴ」을 받침 글자(ᆫ)로 적은 것이다. 바른은 「ㄴ」으로 적는다. 결과를 옮길 때는 「-ㄴ」으로 쓴다.

학교문법과 다른 점

태그셋은 컴퓨터 처리를 위해 만든 것이어서 학교문법과 맞지 않는 부분이 있다. 대표적인 예가 「이다」다. 학교문법에서는 서술격 조사로 보지만 세종 태그셋은 VCP(긍정 지정사)로 따로 분류한다. 「아니다」도 학교문법에서는 형용사인데 태그셋에서는 VCN이다.

그러므로 분석 결과를 쓸 때는 어느 체계를 따르는지 먼저 정해야 한다. 품사를 말할 때는 학교문법 용어로, 태그를 말할 때는 태그로 쓰고, 분석기 화면의 ‘품사’ 열을 그대로 옮겨 적지 않도록 한다.

§ Ⅳ

빠르고 정확하게 분석하는 다섯 단계 Workflow

형태소 하나하나를 모두 의심하면 분석기를 쓰는 의미가 없고, 아무것도 의심하지 않으면 분석기가 틀린 만큼 함께 틀린다. 아래 순서는 다시 확인할 곳을 좁혀 나가는 데 초점을 두었다.

  1. 자료를 정리해서 넣는다

    문장 끝마다 마침표나 물음표를 넣는다. 원문의 띄어쓰기와 철자는 고치지 않는다. 노래 가사처럼 문장부호가 없는 자료는 줄 끝에 마침표를 붙인다.

    문장부호가 있고 없음에 따라 결과가 실제로 달라진다. Kiwi에 「아버지가방에들어가신다」를 부호 없이 넣었더니 마지막의 「-ㄴ다」가 연결어미(EC)로 나왔고, 마침표를 붙이자 종결어미(EF)로 바뀌었다.

  2. 바른에서 설정을 맞추고 분석한다

    자동 붙여쓰기와 자동 띄어쓰기는 끄고, 원형 분석은 켠다. 결과는 ‘형태소 테이블’로 본다.

  3. 다시 확인할 곳에 표시한다

    표를 위에서부터 훑으면서 다음에 해당하는 행만 골라낸다. ① 확률이 90 미만인 것 ② 출처가 ‘학습 사전’이 아닌 것 ③ §Ⅴ에서 다룬 유형(동음어, 불규칙 활용, 축약, ‘-하다’ 용언, 품사 통용, 간투사, 비표준 표기)에 해당하는 것 ④ 지금 분석하려는 대상과 직접 관련된 것. 대개 한 문장에 한두 곳이다.

  4. Kiwi로 한 번 더 분석한다

    같은 문장을 Kiwi에 넣고 표시한 곳만 비교한다. 두 분석기의 결과가 같으면 대체로 넘어가도 된다. 결과가 다르면 둘 중 하나는 틀린 것이므로 다음 단계로 간다. 다만 둘이 똑같이 틀리는 경우도 있다(§Ⅴ의 「시려워」, 「먹엇어요」).

  5. 사전과 문법 지식으로 판단하고 근거를 남긴다

    표제어로 실려 있는지, 품사가 무엇인지, 활용형이 맞는지를 사전에서 확인한다. 그런 다음 문장 안에서 그 말이 어떤 구실을 하는지(다른 말로 바꿀 수 있는지, 어떤 말과 어울리는지) 보고 판단한다. 판단이 갈릴 수 있는 곳에는 「분석기는 ○○로 분석했지만 ~이므로 △△로 본다」처럼 근거를 한 줄 적어 둔다. 나중에 자료를 다시 볼 때나 다른 사람과 결과를 맞춰 볼 때 이 한 줄이 기준이 된다.

§ Ⅴ

분석기가 자주 틀리는 곳 Where Taggers Fail

아래 표는 같은 문장을 두 분석기에 넣어 얻은 결과다(바른은 웹에서 원형 분석을 끈 기본 설정, Kiwi는 0.24 버전, 2026년 10월). ○는 맞음, ✕는 틀림, △는 판단이 필요한 경우를 뜻한다. 분석기는 계속 업데이트되므로 지금 넣으면 결과가 다를 수 있다. 중요한 것은 개별 결과보다 어떤 유형에서 틀리는지를 알아 두는 것이다.

띄어쓰기 없는 중의문아버지가방에들어가신다.아버지/NNG + 가방/NNG + 에 ✕아버지/NNG + 가/JKS + 방/NNG + 에 ○바른은 자동 띄어쓰기를 켜든 끄든 「가방」으로 읽었다. 이 경우에는 바른이 틀렸다.
‘-하다’ 용언공부하는 학생이다.공부하/VV (출처: 내장 사전) △
원형 분석 켬: 공부/NNG + 하/XSV		공부/NNG + 하/XSV형태소 단위로 보면 「공부 + -하- + -는」이다. 바른에서는 원형 분석을 켜야 이렇게 나뉜다.
품사 통용내일 봬요. / 내일 갈게.내일/NNG · 내일/MAG △내일/MAG「내일」은 명사로도 부사로도 쓰인다. 두 문장 모두 조사 없이 서술어를 꾸미므로 부사로 보는 것이 자연스럽다. 바른은 같은 쓰임을 문장마다 다르게 분석했다.
말끝 어미어 그 저기 뭐지?뭐/NP + 이/VCP + 지/EC (56.74%) ✕뭐/NP + 이/VCP + 지/EF ○스스로에게 묻는 말로 문장이 끝난다. 낮은 확률이 이미 틀렸을 가능성을 알려 주고 있었다.
간투사어 그 저기 뭐지그/NP ✕그/IC ○무언가를 가리키는 말이 아니라 말을 고르면서 내는 소리이므로 감탄사(간투사)로 본다.
반복 구성엄마 이거 봐봐.보/VV + 아/EC + 보/VX + 아/EC ✕
(자동 띄어쓰기를 켜면 두 어절로 나뉨)		보/VV + 어/EC + 보/VX + 어/EF ○마지막 「-아」는 명령을 나타내는 종결어미다. 바른은 띄어쓰기 설정에 따라 결과가 달라졌다.
이형태집에 왔다.오/VV + 았/EP ○오/VV + 었/EP △Kiwi는 대표형으로 바꾸어 적는다. 「-았-/-었-」의 교체를 살필 때는 원래 형태로 적는다.
비표준 활용형손이 시려워.시렵/VA (출처: 신조어) △시렵/VA-I △두 분석기 모두 겉으로 드러난 형태를 따라 「시렵다」를 기본형으로 세웠다. 표준어는 「시리다」(활용형 「시려」)다. 노래 가사에 자주 나오는 형태인데, 두 분석기의 결과가 같더라도 판단은 사전을 근거로 한다.
표기 오류엄마가 먹엇어요.먹/VV + 엇/EP먹/VV + 엇/EP둘 다 잘못된 표기를 그대로 따랐다. 전사할 때 표기를 바로잡을지 먼저 정하고 나서 분석기에 넣는다.
합성어와 구큰집에 / 큰 집에큰집/NNG · 크/VA + ㄴ/ETM + 집 ○같음 ○분석기는 띄어쓰기를 그대로 따른다. 원문의 띄어쓰기가 틀려 있으면 분석도 따라서 틀린다. 자동 띄어쓰기를 끄라고 한 것도 같은 이유다.
한 단어로 굳은 말좋아해? / 들어가신다좋아하/VV · 들어가/VV같음사전에 한 단어로 실려 있어서 통째로 분석했다. 단어가 어떻게 만들어졌는지를 다룰 때는 「좋- + -아 + 하-」, 「들- + -어 + 가-」로 다시 나누어 설명해야 한다.
줄어든 말날 좋아해? / 봬요나/NP + ㄹ/JKO · 뵈/VV + 어요 ○같음 ○둘 다 원래 형태를 잘 되살렸다. 준말은 분석기가 비교적 잘 처리하는 편이다.
정리

바른과 Kiwi가 틀린 곳은 서로 겹치지 않았다. 바른이 틀린 「가방」, 「지/EC」, 「그/NP」는 Kiwi가 맞혔고, Kiwi가 틀린 「나는(날다)」은 바른이 맞혔다. 그래서 두 분석기의 결과가 다른 곳만 찾아도 다시 확인해야 할 곳은 대부분 걸러진다. 반면 둘 다 틀리는 곳(비표준형, 표기 오류, 한 단어로 굳은 말의 내부 구조)은 사람이 직접 살펴야 한다.

§ Ⅵ

발화 자료의 형태소 세기 Counting Morphemes

언어치료 분야에서 분석기를 가장 많이 쓰는 경우는 형태소 단위 평균발화길이(MLU-m) 같은 지표를 구할 때다. 분석기를 쓰면 시간은 줄지만, 분석기가 내놓은 형태소 수가 곧 MLU-m이 되는 것은 아니다. 세는 규칙을 먼저 정하고, 분석기 결과를 그 규칙에 맞게 고쳐야 한다.

분석기 결과에서 손봐야 할 것

항목분석기의 처리미리 정해 둘 것
문장부호SF, SP 등을 형태소처럼 따로 낸다항상 뺀다
되살린 「이다」「뭐지」, 「거야」에서 생략된 이/VCP를 되살린다소리 나지 않은 형태소를 셀지
간투사·반복·수정「어」, 「그」, 「저기」를 하나씩 센다미로(maze)로 보고 뺄지
한 단어로 굳은 말「좋아하다」, 「들어가다」를 1개로 센다1개로 볼지, 구성 요소로 나눌지
‘-하다’ 용언설정에 따라 1개 또는 2개로 센다바른의 원형 분석을 켤지 끌지

어느 쪽으로 정해도 괜찮지만, 한 자료 안에서는 같은 도구, 같은 설정, 같은 규칙으로 끝까지 세야 한다. 그리고 결과를 보고할 때 그 규칙을 함께 밝힌다. 도구나 설정이 달라지면 같은 발화라도 형태소 수가 달라지기 때문이다. 예를 들어 「봐봐」는 두 분석기 모두 형태소 4개(보/아/보/아)로 나누었지만, 바른에서 자동 띄어쓰기를 켜면 어절 수가 1개에서 2개로 늘어난다.

많은 발화를 한꺼번에 처리하기 — 파이썬(Kiwi)

발화가 수십 개를 넘어가면 웹에 하나씩 넣는 것보다 코드를 쓰는 편이 빠르다. 구글 Colab이나 자기 컴퓨터의 파이썬에서 아래 코드를 그대로 실행하면 문장부호를 뺀 형태소 수와 MLU-m이 나온다. 위 표에서 말한 항목은 출력을 보면서 따로 고친다.

# 처음 한 번만 설치 !pip install kiwipiepy from kiwipiepy import Kiwi kiwi = Kiwi() utts = ["엄마 이거 봐봐.", "빨간 거 줘.", "나 이거 먹을래.", "아빠가 사 줬어."] SKIP = {"SF", "SP", "SS", "SE", "SO", "SW"} # 문장부호는 세지 않음 counts = [] for u in utts: toks = [t for t in kiwi.tokenize(u) if t.tag not in SKIP] counts.append(len(toks)) print(u, len(toks), " ".join(f"{t.form}/{t.tag}" for t in toks)) print("MLU-m =", round(sum(counts) / len(counts), 2))

실행하면 다음과 같이 나온다. 「빨간」은 빨갛/VA-I + ᆫ/ETM으로, 「줬어」는 주/VX + 었/EP + 어/EF로 나뉜 것을 확인할 수 있다.

엄마 이거 봐봐. 6 엄마/NNG 이거/NP 보/VV 어/EC 보/VX 어/EF 빨간 거 줘. 5 빨갛/VA-I ᆫ/ETM 거/NNB 주/VV 어/EF 나 이거 먹을래. 4 나/NP 이거/NP 먹/VV 을래/EF 아빠가 사 줬어. 7 아빠/NNG 가/JKS 사/VV 어/EC 주/VX 었/EP 어/EF MLU-m = 5.5

바른도 파이썬 패키지(bareunpy)를 제공한다. bareun.ai에 가입해 이메일 인증을 마치면 ‘내정보 확인’에서 koba-로 시작하는 API 키를 받을 수 있다. 키는 개인에게 발급되는 것이므로 과제 파일 등에 적어서 남과 공유하지 않는다.

개인정보

바른 웹과 bareunpy, Colab은 모두 입력한 문장을 외부 서버로 보낸다. 수업 자료나 공개된 문장은 상관없지만, 실습 기관에서 수집한 대상자의 실제 발화는 이름, 장소, 기관명 같은 정보를 지운 뒤에만 넣어야 한다. 가능하면 자기 컴퓨터에 설치한 Kiwi로 처리하는 것이 안전하다. 자기 컴퓨터에서 실행할 때는 첫 줄의 !pip 대신 명령 프롬프트에서 pip install kiwipiepy를 실행한다.
