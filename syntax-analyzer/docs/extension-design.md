# 한국어 문장 분석기 확장 설계안: 논항 중심 분석

작성: 2026-11-10 · 상태: 제안(검토 필요)

이 문서에서는 **[확인]**(자료나 실행으로 확인한 사실), **[추정]**(근거는 있으나 확인하지 못한 것),
**[제안]**(설계 판단)을 구분해 표시합니다.

---

## 1. 목표

현재 분석기는 조사·어미 같은 **형태 정보**로 학교문법의 문장 성분을 판정합니다.
확장의 목표는 **서술어를 중심으로 문장을 보는 논항 구조 분석**입니다.

| 단계 | 학생이 알게 되는 것 | 예: "철수가 영희에게 꽃을 주었다." |
|---|---|---|
| 현재 | 각 어절의 문장 성분 | 주어 · 부사어 · 목적어 · 서술어 |
| 확장 1 | 서술어의 자릿수, 필수 성분과 수의 성분 | '주다'는 세 자리 서술어. '영희에게'는 **필수적 부사어** |
| 확장 2 | 생략된 논항, 관형절의 빈자리 | "새 옷을 샀다" → 주어 자리 비어 있음(생략) |
| 확장 3 | 의미역(선택) | 철수=행위주, 영희=도달점(수혜자), 꽃=대상 |
| 확장 4 | 문법 요소에 따른 논항 변화 | 먹다(두 자리) → 먹이다(세 자리, 사동) |

[제안] 저장소의 15주 강의 구성 중 제10주 '문장의 구성', 제11주 '문장의 확대',
제12주 '문법 요소의 기능과 의미'에 각각 연결할 수 있습니다(주차 제목은 저장소 파일로 확인).

## 2. 현재 엔진의 한계

[확인] 다음은 시제품 분석과 자동 검사에서 확인한 사항입니다.

1. **서술어의 자릿수 정보가 없습니다.** 그래서 필수적 부사어('영희에게 주다', '책상에 넣다')와 수의적 부사어('어제', '학교에서')를 구별하지 못합니다.
2. 같은 이유로, 논항이 관형절과 주절 중 어느 서술어에 속하는지 위치 규칙으로만 정합니다. 예를 들어 '학교에 간 사람'의 '학교에'를 주절에 붙일 수 있습니다.
3. 보조사가 붙은 체언('사과는')의 격을 정하지 못해 주어로 추정합니다.
4. 생략된 논항을 표시하지 않습니다.

이 한계는 대부분 **서술어별 논항 정보(격틀·문형 정보)** 가 있으면 줄일 수 있습니다.

## 3. 필요한 기능

### A. 분석 엔진

#### A1. 서술어 논항 사전(격틀 사전) — 핵심
서술어의 뜻마다 어떤 논항을 어떤 조사로 요구하는지 적은 사전입니다.

```json
{
  "lemma": "주다", "pos": "VV", "sense": 1,
  "gloss": "물건 따위를 남에게 건네어 가지거나 누리게 하다.",
  "places": 3,
  "frame": [
    {"role": "주어",   "case": ["이/가", "께서"],          "required": true, "semantic": "행위주"},
    {"role": "부사어", "case": ["에게", "한테", "께"],      "required": true, "semantic": "도달점"},
    {"role": "목적어", "case": ["을/를"],                  "required": true, "semantic": "대상"}
  ],
  "example": "철수가 영희에게 꽃을 주었다.",
  "source": "교사 작성"
}
```

- [제안] 처음에는 **교사가 직접 편집하는 작은 사전**(교재 예문에 나오는 서술어 100~200개)으로 시작합니다. 파일은 JSON이나 YAML로 저장소에 두고, 버전 관리를 합니다.
- [확인] 바른의 우리말샘 사전 검색(`SearchDict`)은 뜻풀이, 어깨번호, 우리말샘 번호(targetCode), 용례를 돌려줍니다. 다만 **문형 정보는 응답에 없었습니다**('주다' 실제 조회로 확인).
- [추정] 사전의 문형 정보를 가져올 수 있는 후보는 아래와 같습니다. 제공 여부와 이용 조건은 확인이 필요합니다.
  - 표준국어대사전: 사전 정보로 '문형'을 싣고 있습니다. 하지만 오픈 API가 문형을 돌려주는지는 확인하지 못했습니다.
  - 한국어기초사전 API: 비공식 라이브러리 문서에 `pattern_info`(문형) 항목이 있다고 되어 있습니다(공식 명세는 확인하지 못함).
  - 21세기 세종계획 전자사전(용언 사전의 격틀): 연구에 널리 쓰였습니다. 현재 배포처와 라이선스는 확인하지 못했습니다.

#### A2. 격틀을 이용한 논항 연결(자리 채우기)
- [제안] 지금의 '위치 우선 규칙'을 '격틀 우선 규칙'으로 바꿉니다.
  1. 서술어마다 격틀의 빈자리를 만듭니다.
  2. 앞의 어절을 조사 정보에 맞는 빈자리에 배정합니다.
  3. 남는 성분은 **수의적 성분(부가어)** 으로 표시합니다.
- 격틀이 없는 서술어는 지금 규칙으로 처리하고 '격틀 정보 없음'으로 표시합니다.
- 기대 효과:
  - 필수적 부사어를 구별합니다.
  - 관형절과 주절 중 어디에 연결할지 더 정확해집니다.
  - 보조사가 붙은 체언의 격을 추정할 수 있습니다. 예: '사과는 먹었다'에서 '먹다'의 목적어 자리가 비어 있으므로 '사과는'을 목적어로 봅니다.

#### A3. 생략 논항과 관형절의 빈자리
- [제안] 격틀의 필수 자리가 채워지지 않으면 화면에 '∅(생략)'으로 표시합니다.
- 관형절에서는 꾸밈을 받는 체언이 관형절 서술어의 어느 자리에 해당하는지 보여 줍니다. 예: "내가 어제 산 **책**" → '책'은 '사다'의 목적어 자리.
- 빈자리가 없는 관형절은 동격 관형절 후보로 표시합니다. 예: "그가 범인이라는 **사실**".
  - 관계 관형절과 동격 관형절의 구분은 학교문법 수업 내용과 바로 연결됩니다.

#### A4. 뜻에 따른 격틀 선택
- 같은 서술어도 뜻에 따라 문형이 다릅니다. 예: '주다'의 여러 뜻, 보조 용언 '주다'.
- [확인] 바른 형태소 분석의 `with_sense`(베타) 기능은 형태소에 어깨번호와 뜻풀이, 우리말샘 번호를 붙여 줍니다.
- [제안] 격틀 사전 항목에 우리말샘 번호를 함께 적어 두면, 분석 결과의 뜻 번호로 알맞은 격틀을 고를 수 있습니다.
  - 베타 기능이므로 정확도는 수업 예문으로 따로 확인해야 합니다.
  - 이 기능을 쓰면 응답 시간이 늘어날 수 있습니다.

#### A5. 의미역(선택, 고급)
- [제안] 행위주, 경험주, 대상, 도달점, 출발점, 장소, 도구 등 **작은 의미역 집합**을 정해 격틀에 함께 적습니다.
- 의미역 체계는 학자와 교재마다 다릅니다. 어느 체계를 쓸지 먼저 정하고 문서에 근거를 밝혀야 합니다.

#### A6. 문법 요소와 논항 변화
- [제안] 사동·피동, 높임과 함께 논항 구조가 어떻게 바뀌는지 보여 줍니다.
  - 사동: 먹다 → 먹이다. 주어가 하나 늘고, 원래 주어는 '에게'나 '을/를'로 나타납니다.
  - 피동: 잡다 → 잡히다. 목적어가 주어로 바뀝니다.
- [추정] 바른이 '먹이다'를 한 단어(VV)로 분석하는지, '먹+이+다'로 나누는지는 확인이 필요합니다. 한 단어로 분석하면 사동사와 원래 동사의 대응표를 사전에 따로 두어야 합니다.

### B. 화면과 수업 기능

| 기능 | 내용 | 비고 |
|---|---|---|
| B1. 논항 구조 보기 | 서술어마다 '누가 / 누구에게 / 무엇을' 자리 카드. 채워짐·생략·부가어를 색으로 구분 | A1~A3 필요 |
| B2. 학습 모드 | 학생이 먼저 성분·자릿수를 고르고 '확인'을 누르면 정답과 근거를 보여 줌 | 지금 엔진으로도 일부 가능 |
| B3. 주차별 예문 세트 | 10~12주차 수업 예문을 묶어 바로 불러오기. 저장된 결과를 써서 사용량 차감 없음 | 교사가 예문 제공 |
| B4. 판정 의견 보내기 | 학생·교사가 "판정이 이상해요"를 누르면 문장과 의견이 저장되어 격틀 사전 보완에 사용 | 저장소 필요(아래 C3) |
| B5. 교재 기준 전환 | '-고'의 대등/종속, 접속 부사 등 교재마다 다른 항목을 기준 교재에 맞춰 표시 | 기준 교재 결정 필요 |

### C. 운영과 품질

- **C1. 평가 세트**
  - [제안] 교재 예문에 교사가 정답(성분, 자릿수, 논항)을 붙인 평가 세트를 만듭니다.
  - 규칙을 바꿀 때마다 정확도를 자동으로 잽니다. 지금의 자동 검사 28개를 넓히는 방식입니다.
- **C2. 격틀 사전 반자동 구축** — 바른 MCP 활용
  1. 바른 사전 검색으로 서술어의 뜻별 용례를 가져옵니다(용례 제공 확인).
  2. 그 용례를 바른 형태소 분석에 넣어 함께 나오는 조사의 분포를 집계합니다.
  3. 격틀 후보를 자동으로 만들고, 교사가 검토해 확정합니다.
  - Claude Code에 바른 MCP를 연결해 이 작업을 대화로 진행할 수 있습니다.
  - [주의] 용례 분석은 어절 사용량을 소모합니다. 무료 구간(5만 어절)을 고려해 서술어 수를 조절해야 합니다.
- **C3. 저장소**
  - [추정] Hugging Face 무료 Space는 다시 시작하면 파일이 초기화되는 것으로 알고 있습니다(확인 필요).
  - B4의 의견 수집처럼 오래 보관할 자료는 Hugging Face Dataset 저장소나 GitHub 이슈 같은 별도 저장소가 필요합니다.
- **C4. 이용 조건**
  - [확인] 바른 라이선스 정책은 "비상업 목적이더라도 사용자들을 대상으로 상시 운영 중인 서비스"를 상용으로 봅니다.
  - 정식 수업 운영 전에 바른 측에 문의하거나 연구 목적 무료 신청을 검토해야 합니다.

## 4. 단계별 계획(제안)

| 단계 | 내용 | 산출물 |
|---|---|---|
| 0. 조사·결정 | 문형 정보 출처와 이용 조건 확인, 의미역 체계와 기준 교재 결정, 평가 예문 수집 | 결정 문서, 평가 세트 초안 |
| 1. 격틀 사전 v0 | 교재 서술어 100~200개 격틀 작성(교사 검토), 엔진에 자리 채우기 연결 | 자릿수·필수 부사어·생략 논항 표시 |
| 2. 화면 | 논항 구조 보기(B1), 학습 모드(B2), 주차별 예문(B3) | 수업 시범 운영 |
| 3. 사전 확장 | 뜻 구분 연계(A4), 용례 기반 반자동 구축(C2), 의견 수집(B4) | 격틀 사전 v1 |
| 4. 고급 | 의미역(A5), 사동·피동에 따른 논항 변화(A6) | 고급 과정용 기능 |

## 5. 결정이 필요한 사항

1. **분석 범위**: 의미역(A5)까지 갈지, 자릿수와 필수 성분까지만 다룰지
2. **기준 문법**: 어느 교재·문법서를 판정 기준으로 삼을지(교재마다 다른 항목의 처리 기준)
3. **격틀 사전 작성 방식**: 교사가 직접 작성·검토할지, 반자동 후보 생성(C2)을 먼저 할지
4. **우선순위**: 분석 엔진(A1~A3)과 학습 모드(B2) 중 무엇을 먼저 할지
